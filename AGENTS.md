# Octrie Site — Agent Context

## What this repo is
Static HTML/CSS/JS website for octrie.com, deployed via GitHub Pages with a custom domain.
No build step — all files are plain HTML, CSS, and JS. Edit and push; GitHub Pages deploys automatically.

## Repo structure
```
/                        ← homepage (index.html) + shared styles.css, nav.js
/about/                  ← about page (Tim Tafel, DFW, contact)
/solutions/              ← custom-builds landing page
/tools/                  ← real-estate calculator index (orphaned from nav; Gumroad links in)
/library/                ← resource library (orphaned from nav, placeholder content)
/wholesale-calculator/   ← built output of the Wholesale Calculator 2 project
/rehab-calculator/       ← built output of the Rehab Cost Estimator project
404.html                 ← custom GitHub Pages 404 (uses absolute / paths)
robots.txt, sitemap.xml  ← SEO plumbing
nav.js                   ← shared navigation JS (included on all pages)
styles.css               ← global site styles AND design tokens (single combined file)
bg-concrete.jpg          ← concrete texture background (kept compressed ~400 KB — do not replace with a raw photo)
```

## Deploy workflow
1. Edit files directly in this repo
2. Commit and push to `main`
3. GitHub Pages auto-deploys to octrie.com — no build command needed

## Calculator tools
The calculators (`/wholesale-calculator/`, `/rehab-calculator/`) are **built outputs** from separate source repos.
Do NOT hand-edit the calculator `index.html` files — they are generated by their respective build processes.
They are fully self-contained (own CSS/fonts); root styles.css changes never affect them.

## Positioning (as of 2026-07)
General, industry-agnostic messaging: customer follow-up & call automation for local service
businesses ("Never miss another customer call"). Do NOT reintroduce real estate/trades niching
on the homepage or about page. /tools/ and /library/ are legacy RE-era pages, intentionally
orphaned from navigation — leave their content alone unless asked.

## Design system
- All tokens (colors, spacing, radii, type) live at the top of `styles.css` — there is no separate token file
- Light concrete/brutalist palette; the page is a light "card" floating over a fixed concrete photo background
- Amber brand accent (`--oc-vertical-accent: #B8922A`, deep variant `#8A681A` for small text) — scoped under `#home` (the homepage `<body id="home">`) so other pages keep neutral buttons
- Fonts: DM Sans (headings/body), DM Mono (labels/buttons), Syne 800 (wordmark only) — loaded via `<link>` tags in each page's `<head>` (NOT `@import` in CSS); keep the weight list trimmed to what's used
- CSS custom properties drive all colors, spacing, and radii — never hardcode values that have a token
- Visual identity is FROZEN by owner decision — copy changes fine, design changes need explicit approval

## Conventions
- No frameworks, no npm, no bundler — pure HTML/CSS/JS only
- Keep pages self-contained; share only nav.js and styles.css globally
- Nav on every page: Services / How it works / About (anchors resolve to homepage sections)
- Footer on every page includes Contact (mailto:info@octrie.com) and a phone link
- **Phone number is obfuscated against scraping**: never write the raw number (307-761-0727 in
  any format) directly into HTML. Use `<a data-tel="7270167703" href="mailto:info@octrie.com">`
  (digits reversed) — `nav.js` reverses them back and assembles the real `tel:` link + formatted
  display text at runtime. Optional `data-tel-label="Call "` attribute prepends static text (e.g.
  the About page CTA reads "Call (307) 761-0727"). This keeps the number out of raw HTML that
  scrapers harvest, while degrading gracefully to a working mailto link if JS fails to run.
- Never touch `CNAME`
- Safety ritual before risky changes: `git tag <name> && git push origin <name>` (existing rollback tags: `before-general-homepage`, `before-accent-color`, `before-site-consistency`)
